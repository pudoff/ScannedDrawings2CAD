# Запуск ScannedDrawings2CAD через Docker

Docker Compose запускает весь сервис: PostgreSQL, веб-интерфейс Web V31, обработчик чертежей и обработчики ручных и табличных правок. Python, `.venv`, установка пакетов через `pip` и Windows runtime ZIP на компьютере не требуются.

## 1. Подготовить Docker

- На Windows/macOS установите и запустите Docker Desktop. На Windows используйте режим **Linux containers**.
- На Linux нужны работающий Docker Engine и Docker Compose v2.
- Docker должно быть доступно не менее **6 ГБ оперативной памяти**; одновременная обработка нескольких задач может потребовать больше. GPU не нужен. Образ предназначен для `linux/amd64`.
- Для получения репозитория нужен Git. Первая сборка скачивает образы и зависимости из Docker Hub, Debian и PyPI.

Откройте PowerShell или терминал и проверьте:

```bash
docker version
docker compose version
```

В выводе `docker version` должны быть разделы `Client` и `Server`. Если Docker Engine недоступен, сначала запустите Docker Desktop и дождитесь его готовности.

## 2. Получить проект

Если репозитория ещё нет:

```bash
git clone https://github.com/pudoff/ScannedDrawings2CAD.git
cd ScannedDrawings2CAD
```

Если репозиторий уже есть, откройте терминал **в его корне**, где лежит `compose.yaml`, и обновите код:

```bash
git pull --ff-only
```

Если Git сообщает о конфликте с локальными изменениями, сохраните их перед обновлением. Не нужно заново клонировать проект поверх существующей папки.

Если ранее запускали сервис через Python, дождитесь завершения обработки и остановите его через **Ctrl+C в терминале запуска**. Docker создаёт собственные БД и хранилище; документы из прежней Windows-установки автоматически не переносятся. Старую `.venv` для Docker чинить или удалять не требуется.

## 3. Собрать и запустить

Из корня проекта выполните:

```bash
docker compose up --build -d --wait --wait-timeout 300
docker compose ps -a
```

Первая сборка может занять несколько минут. `--wait` ждёт готовности сервисов; `300` — время ожидания запуска, а не лимит загрузки зависимостей или конвертации чертежа. После запуска терминал можно закрыть, Docker должен продолжать работать.

Ожидаемые состояния в `docker compose ps -a`:

| Сервис | Состояние |
|---|---|
| `db`, `web` | `Up … (healthy)` |
| `worker`, `corrections`, `tables` | `Up` |
| `setup` | `Exited (0)` — штатное завершение одноразовой подготовки БД |

Откройте **http://127.0.0.1:8000**. Дополнительная проверка доступности: **http://127.0.0.1:8000/health**, ответ содержит `"status":"ok"`.

## 4. Преобразовать чертёж

1. Загрузите PNG, JPEG или скан-PDF через веб-интерфейс.
2. Оставьте выбранный профиль **«CAD · целые объекты и рамка (эксперимент)»** (`native_cad_layers_draft`).
3. Дождитесь завершения обработки, проверьте предпросмотр и скачайте DXF нужной страницы.

Обработка выполняется на CPU; длительность зависит от размера и содержания листа. Сложный чертёж может обрабатываться больше 15 минут, даже если PNG занимает меньше 1 МБ. Лимит Docker по умолчанию — **30 минут на задание**; ожидание очереди добавляется отдельно. Профиль `native_observations` выдаёт наблюдения без DXF, а `baseline` предназначен для уже существующих векторов PDF.

В текущем Web V31 выполняйте **табличные правки до ручных правок метаданных**: табличный редактор не принимает версию, уже содержащую такую ручную правку. Docker использует **DejaVu Sans** вместо Cambria, поэтому внешний вид и метрики текста могут отличаться от Windows-сборки. Для одинакового отображения DXF установите DejaVu Sans на компьютере с CAD.

## Остановка, повторный запуск и обновление

Перед остановкой дождитесь завершения текущих задач. Остановить сервис:

```bash
docker compose down
```

Повторно запустить уже собранную версию:

```bash
docker compose up -d --wait --wait-timeout 300
```

Обновить код и пересобрать сервис после завершения текущих задач:

```bash
git pull --ff-only
docker compose up --build -d --wait --wait-timeout 300
```

Одного `git pull` недостаточно: код находится внутри образа и применяется после пересборки. База и документы сохраняются в Docker volumes `database` и `documents`. Обычный `docker compose down` их сохраняет; **`docker compose down -v` удаляет данные**.

## Если запуск или обработка не удаются

Сначала проверьте состояния и последние сообщения:

```bash
docker compose ps -a
docker compose logs --tail 100 db setup web worker corrections tables
```

| Проблема | Что сделать |
|---|---|
| `docker` не найден | Установите Docker и откройте новый терминал |
| `Cannot connect to the Docker daemon`, ошибка pipe / Docker Engine | Запустите Docker Desktop, дождитесь готовности и проверьте `docker version`; на Windows используйте Linux containers |
| `no configuration file provided` | Перейдите в корень ScannedDrawings2CAD, где находится `compose.yaml` |
| `unknown flag: --wait` | Обновите Docker Compose; команду нужно выполнять как `docker compose`, с пробелом |
| Порт 8000 занят / `port is already allocated` | Остановите прежний Python-сервис или задайте другой порт, как описано ниже |
| `setup` завершился с ненулевым кодом, `web` — `unhealthy`, контейнер — `Restarting` | Посмотрите логи соответствующего сервиса; `setup: Exited (0)` является нормой |
| Истекло ожидание 300 секунд | Проверьте `ps -a` и логи: контейнеры могли продолжить запуск. Истечение ожидания само по себе их не останавливает |
| Не скачиваются образы или пакеты | Проверьте доступ к Docker Hub, Debian и PyPI, затем повторите команду сборки |
| Задание долго в очереди или обрабатывается | Убедитесь, что `worker` имеет состояние `Up`, и откройте его логи. Крупный лист может обрабатываться дольше; не отправляйте тот же файл многократно |
| «Обработка заняла слишком много времени» | Сработал лимит задания. Обновите сервис; проверьте, что старый `.env` не задаёт `CAD_SERVICE_TIMEOUT_SECONDS=900`. При необходимости увеличьте лимит и создайте новую версию документа по [инструкции в DOCKER.md](DOCKER.md#лимит-обработки) |
| Контейнер завершился с кодом 137 | Проверьте доступную Docker память и логи; процесс мог быть остановлен из-за нехватки памяти |
| `did not find executable … python.exe` при запуске `.venv` | Это ошибка старого Windows-окружения. Для Docker используйте команды выше, без `.venv\Scripts\python.exe` и `start_profiles_v27.py` |

Для другого порта создайте файл **`.env`** рядом с `compose.yaml` (именно `.env`, не `.env.txt`) или измените в существующем файле эту строку, сохранив остальные настройки:

```dotenv
CAD_HTTP_PORT=8001
```

Затем выполните `docker compose up -d --wait --wait-timeout 300` и откройте **http://127.0.0.1:8001**. Внутренний порт контейнера менять не нужно.

Наблюдать сообщения во время обработки:

```bash
docker compose logs -f --tail 100 web worker corrections tables
```

**Ctrl+C здесь прекращает просмотр логов, сервис продолжает работать.**

## Необязательная проверка установки

После успешного запуска можно проверить компоненты и выполнить сквозные тесты:

```bash
docker compose run --rm --no-deps web check
docker compose exec -T web python /app/docker/smoke_test.py
docker compose exec -T web python /app/docker/smoke_edits.py
```

`smoke_test.py` создаёт тестовый документ и проверяет загрузку, преобразование, скачивание и структуру DXF. Следующая команда проверяет табличную и ручную правки именно этого документа. Выполняйте их по порядку; для повторной проверки обеих очередей сначала снова запустите `smoke_test.py`. Тестовые документы и версии остаются в интерфейсе.

Резервные копии и устройство Docker-установки — [DOCKER.md](DOCKER.md). Альтернативный запуск без Docker — [WINDOWS_SETUP.md](WINDOWS_SETUP.md).
