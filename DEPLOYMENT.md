# Передача бинарного комплекта коллегам

Git хранит код, Web-ресурсы, конфигурации и проверяемый индекс. `.venv` создаётся установщиком. Точные Python-библиотеки, PostgreSQL и OCR-модели передаются отдельно в `runtime-win-cp314-v31-20261125.zip`.

Архив подготовлен в **`release-assets/runtime-win-cp314-v31-20261125.zip`**. Он исключён из Git; не содержит датасет, пользовательские документы, БД, кэш или исследовательские отчёты. Его размер и SHA-256 записаны в `runtime-distribution.json`, рядом есть файл `.sha256`.

Владельцу репозитория:

1. Опубликовать обновлённый код, включая корневые `setup_repository.py`, `run_service.py`, README/QUICKSTART, `runtime-distribution.json`, `runtime/compact/` и весь состав исходников сборки. Удаления старых файлов при обновлении также должны войти в commit; перед commit проверьте `git status`.
2. Создать GitHub Release для этого commit и приложить ZIP из `release-assets` и его `.sha256`. Сам факт локальной подготовки **не означает, что архив уже загружен на GitHub**.
3. Передать коллеге ссылку на Release. Коллега клонирует соответствующий commit, скачивает ZIP и выполняет команды из QUICKSTART.

Можно передать тот же ZIP через файловое хранилище: установщик всё равно сверяет закреплённые SHA. Публиковать Release или менять удалённый Git автоматически эти скрипты не будут.

Не публикуйте `.update-backups`, `.venv`, журналы, пользовательские базы и документы. После локального обновления предыдущие файлы сохранены в `.update-backups/`; это резервная копия для владельца, она не нужна коллеге.

Один `pip install` не воспроизводит byte-for-byte инвентарь этой сборки: установка колёс может создавать другие RECORD/launcher-файлы и не устанавливает PostgreSQL. Поэтому runtime распространяется как проверенный комплект, а `requirements.runtime.lock` служит описанием версий. Новый переносимый pip/bootstrap с перепостроением инвентаря — отдельная задача.

Текущие изменения повышают надёжность Web и исполнения заданий (V28–V31). Алгоритмы CV/OCR/CAD и принятые модели сохранены; исследовательские классификаторы из последних отрицательных сравнений не включены.

## Обновление просмотрщика V32, 26.11.2026

Передайте все файлы из [списка изменений](UPDATED_FILES_2026-11-26.md) одним обновлением, включая index/trust/runtime-distribution/runtime-manifest. Проверка SHA остаётся включённой. Библиотеки и модели побайтно прежние, используется тот же ZIP V31 и его прежний SHA. Пользователю с установленным runtime достаточно обновить код, выполнить `run_service.py --check`, перезапустить `run_service.py --open` и обновить страницу Ctrl+F5. Новых удаляемых файлов нет; БД и документы сохраняются.
